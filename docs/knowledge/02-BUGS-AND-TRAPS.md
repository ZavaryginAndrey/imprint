## 🔴 КРИТИЧЕСКОЕ — процессное (стоило реальных данных)

### CRIT-1. Тестирование онбординга уничтожает реальные данные
- **Что случилось.** Чтобы проверить путь «свежая установка», в фазе 4 форсировали `pm clear`
  (HISTORY §13.3). Это стёрло **недельную реальную историю задач** на боевом устройстве.
  Простой `uninstall + install` не помог: Android Auto Backup (`allowBackup=true`) возвращал prefs,
  и эвристика «пустой store = свежая установка» видела апгрейд (HISTORY §13.4).
- **Корень.** Устройство разработчика = боевое устройство пользователя. Одна `applicationId`,
  один сторедж, никакого экспорта.
- **Что заложить в новый проект СРАЗУ, до первой фичи:**
  1. **`debug` build type со своим `applicationIdSuffix = ".debug"`** — debug и release живут
     параллельно, `pm clear` на debug не трогает боевые данные.
  2. **Экспорт/импорт БД в файл** (JSON или копия `.db`) — руками, локально, в первой же версии.
     Это не «Google-синхронизация» и принципу «локально, офлайн» не противоречит.
  3. **Debug-триггер «показать онбординг заново»** — сбрасывает только флаг онбординга,
     БД не трогает (POLISH DEV-1, так и не сделано).
  4. Решить осознанно, что делает `allowBackup` — он **тихо возвращает prefs** и ломает
     любую эвристику «свежая установка».

## 🟠 Открытые баги на момент заморозки (v1.4.0)

### UI-3. Клавиатура смещает шапку приложения вверх (регресс)
- **Симптом.** При фокусе в поле «Новая задача…» открытая IME **сдвигает шапку** — заголовок
  «День»/подзаголовок уезжают за верхний край. Видно и в инлайн-редакторе, и в нижнем поле.
- **Причина (гипотеза).** `imePadding()`/`WindowInsets` применены **на корне**, а не на контенте;
  либо `windowSoftInputMode` толкает весь layout.
- **Правило для нового проекта.** Шапка фиксирована; поджимается/скроллится **только** список
  и поле ввода. `imePadding()` — на контенте, не на корневом `Scaffold`.

### FUNC-2. Выполненную задачу нельзя корректно отправить в бэклог
- **Симптом.** Завершённая задача при отправке в бэклог остаётся в истории. Дальше расходится:
  обычная — при возврате в День статус сохраняется (ок); **рутинная** — статус сбрасывается на
  undone и запись **исчезает из истории**.
- **Причина.** Выполненность обычной задачи хранится **на строке**, а у рутины **выводится из
  журнала событий** (`DONE`/`SKIPPED` по `dayKey`). Две разные модели истинности → рассинхрон.
- **Согласованное решение.** Запретить отправку в бэклог **выполненных** задач (скрыть/задизейблить
  действие). Простой инвариант, устраняющий рассинхрон.
- **Урок для нового проекта.** ⚠️ **Не держать два источника истины о «выполнено».** Либо всё
  из журнала, либо всё со строки. Смешение породило этот баг и будет порождать новые.

### UI-2. i18n не сделан
- Всё только на русском. Строки уже идут через `stringResource` (хорошо), но локаль одна:
  `values/` = русский. Для мира правильно: **`values/` = английский, `values-ru/` = русский**.
- Внимание при переводе: массивы дней недели, plurals, кавычки/типографика, длины строк, формат дат.
- **Для нового проекта:** сразу `values/` = английский, `values-ru/` = русский. Переделывать потом дороже.

## 🟡 Платформенные грабли Android (дорого стоили, легко повторить)

### AND-1. Foreground-сервис из будильника запрещён на Android 14+
- Первая версия оверлея была foreground-сервисом (`specialUse`) → на A14 (target 36)
  `startForeground` из фонового broadcast **запрещён** (`BFGS denied`).
- **Правильно:** `SYSTEM_ALERT_WINDOW` сам разрешает `addView` из фона; видимое overlay-окно
  удерживает процесс живым. **НЕ возвращать сюда foreground-сервис.**

### AND-2. `USE_FULL_SCREEN_INTENT` — тупик
- Полноэкранное напоминание на локскрине: жёстко гейтится Play на Android 14+ (риск ревью),
  и **будит экран впустую** — ровно тогда, когда никто не смотрит.
- **Правильно (принято в v1.3.0):** экран заблокирован → обычное уведомление со списком
  (`InboxStyle`, `VISIBILITY_PRIVATE` — названия скрыты на локскрине, видны в шторке после
  разблокировки). Плашка — только при активном экране. Разрешение удалено.

### AND-3. `ACTION_USER_PRESENT` не работает как триггер
- Попытка показать плашку сразу после разблокировки провалилась: сигнал **не доставляется
  манифест-ресиверам** (с Android 8), а рантайм-ресивер жив только пока жив процесс — который
  система убивает после отработки будильника. Foreground-сервис ради этого противоречит философии.
- **Правильно:** ничего не делать, плашка придёт на ближайшем тике.

### AND-4. Doze троттлит `allow-while-idle`
- Интервал 15 мин фактически становится ~20 мин. Впечатывание это терпит.
- Подсказка «отключить оптимизацию батареи» — есть, но физику не отменяет.
- `SCHEDULE_EXACT_ALARM` через `ACTION_REQUEST_SCHEDULE_EXACT_ALARM`; при отказе — неточные.
  **`USE_EXACT_ALARM` не брать** (риск Play).

### AND-5. Пропущенный сброс дня надо догонять
- Выключенный телефон / force-stop → сброс дня не случился. Нужна метка последнего сброса в prefs
  и догон при старте (`catchUpDailyResetIfMissed`).

### AND-6. Исключение внутри `goAsync()` роняет процесс молча
- Нужен `CoroutineExceptionHandler` в асинхронной обработке broadcast-ресиверов.

## 🟡 Грабли Jetpack Compose

### CMP-1. `Modifier.pointerInput(keys)` замыкается на протухшее состояние
- **Симптом.** Сворачивание секции группы работало «через раз».
- **Причина.** Корутина жеста не перезапускалась (ключи стабильны), `onTap` держал `isCollapsed`
  из первого рендера.
- **Фикс.** `rememberUpdatedState` для колбэков; ключи сузить до минимально необходимых.

### CMP-2. Дубликат id в `LazyColumn` = краш
- **Симптом.** При DAY⇄BACKLOG-переходе два потока Room не синхронны → один id ненадолго
  в обоих списках → краш по ключу.
- **Фикс.** В чистой функции сборки списка исключать «виртуальное появление», если id уже
  присутствует как реальная строка.

### CMP-3. Авто-закрытие по пустому списку срабатывает мгновенно
- **Причина.** ViewModel стартует с `emptyList()` → «список пуст» ещё до загрузки.
- **Фикс.** Флаг `everHadItems`.

### CMP-4. Клик на всей строке = случайные отметки
- **Симптом.** «После оверлея задачи сами становятся выполненными».
- **Фикс.** Обработчик только на элементе-галочке (с увеличенным хит-таргетом), не на строке.

### CMP-5. Свайп-удаление срабатывает слишком легко
- **Фикс.** `positionalThreshold = 0.5` **плюс** проверка фактического смещения при отпускании
  (`requireOffset()` vs `rowWidth * 0.5`). Одного порога мало.

### CMP-6. Поле ввода не отпускает фокус при сворачивании клавиатуры
- Ловился дважды (§8.8, потом регресс в Бэклоге §12.3). Нужно следить за `WindowInsets.ime`
  и делать `clearFocus()`. **Регрессирующее место — покрыть тестом/чек-листом.**

### CMP-7. Заголовок/таймпикер наследуют брендовый serif и «гуляют»
- Цифры в `TimePicker` в Playfair прыгали по ширине. Фикс: локальный `MaterialTheme` с Inter +
  `tnum` (tabular figures). **Правило: все числовые данные — моноширинными цифрами.**

### CMP-8. Длинные строки в чипах/диалогах ломаются на слоги
- «Выходные» разваливалось на «Вых/одн/ые», Сб/Вс уезжали за край.
- **Фикс.** `FlowRow` вместо `Row` + `horizontalScroll`. Чип переносится целиком.

### CMP-9. Дёрганый авто-скролл
- Скролл к раскрытой группе перерисовывал экран рывком. Фикс: скроллить **только** когда элемент
  выходит за нижнюю границу вьюпорта, и на минимальную дельту.

## 🟡 Грабли Room / данных

### DB-1. Переименовать таблицу «по дороге» нельзя
- Room валидирует сущности против таблиц по версии БД. Переименование + удаление сущности пришлось
  бы делать одним заходом с миграцией. Старая `task_history` осталась **замороженной** (`@Entity`
  без записи) как бэкап-источник импорта; дроп — следующей миграцией.
- **Урок:** планировать удаление таблиц отдельным релизом, не смешивать с добавлением.

### DB-2. Поток с `WhileSubscribed`, который никто не собирает, отдаёт пустой `.value`
- **Симптом.** Свайпы и тумблеры **молча** не работали.
- **Фикс.** Для разовых резолвов — авторитетный запрос в БД, не поток.

### DB-3. Залипшее `SKIPPED` скрывает заново созданную сущность
- Переключение рутины оставляло сегодняшнее `SKIPPED` → рутина не появлялась.
- **Фикс.** При включении рутины чистить сегодняшние `DONE`/`SKIPPED`.

### DB-4. Час сброса датировал историю следующим днём
- История датировалась моментом архивации (час сброса, 4 утра), а не моментом выполнения →
  **неверный день недели** в аналитике. Пришлось делать сдвиг при импорте (на полдень предыдущего
  логического дня).
- **Правильно с самого начала:** каждое событие штампуется **`dayKey` логического дня**
  (`YYYY-MM-DD`), вычисленным от часа сброса **в момент записи**.

### DB-5. Счётчики вместо журнала = миграция на каждый вопрос
- Со счётчиками каждый новый продуктовый вопрос требует миграции и **не имеет исторических данных**.
  С журналом событий — правка запроса по уже накопленному.
- **Правило:** сразу append-only журнал; денормализовать в событие `title`/`groupId`/`isRoutine`,
  чтобы переименование или удаление задачи **не переписывало прошлое**.

### DB-6. Контент напоминаний, собираемый в трёх местах, расходится
- Плашка брала список сама, локскрин фильтровал поток в UI, уведомление не показывало задач вовсе.
- **Правило:** **одна чистая функция отбора**, обе поверхности берут её. Иначе впечатываемый набор
  «плавает» между поверхностями и механизм не работает.

## 🔵 Прочее / архитектурное

- **`isMinifyEnabled = false`** → расширенный набор Material-иконок уезжает в APK почти целиком.
  R8 включить до беты.
- **Ротация обязательна.** Без неё всё за пятой позицией невидимо навсегда.
- **Debug-only ветка не была огорожена `BuildConfig.DEBUG`** — POLISH DEV-1 так и не сделан.
- **Схема БД должна экспортироваться** (`room.schemaLocation`, `exportSchema = true`) и коммититься —
  иначе следующая миграция пишется вслепую.
