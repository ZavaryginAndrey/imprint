# W4 — Веб-UI: store, раскладка, действия

**Дата:** 2026-09-30 · **Статус:** дизайн согласован в чате; W4a реализован (план
[2026-09-30-w4a-web-client.md](../plans/2026-09-30-w4a-web-client.md)); W4b — свой план
**Фаза:** [W4-web-ui.md](../../../imprint2.0/W4-web-ui.md) · **Зависит от:** W3 · **Теги:** `web-w4a`, `web-w4`
**Источник правды по виду и поведению:** [05-web-ux.md](../../../imprint2.0/05-web-ux.md) (заморожен) и
живая сборка [landing/index.html](../../../imprint2.0/landing/index.html) — эталон вида; её код **не**
переносится, приложение пишется заново на React.

## Зачем

Настоящий веб-клиент вместо W2-пробника: День и Бэклог, сайдбар с группами, ввод, строка задачи с
действиями, вход. Нажатие не ждёт сеть (P3), правка в одной вкладке видна в другой без действий
пользователя, правил домена в `apps/web` нет (P1).

**Успех:** человек входит на dev через Google, добавляет, отмечает, переносит и удаляет задачи — всё
отображается мгновенно, а вторая вкладка видит это без перезагрузки.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Объём | **W4a** — рабочий десктопный клиент; **W4b** — полный UX (повтор, шаги, правый клик, перетаскивание, мобильный, все e2e §8). Спек общий, планы свои | Фаза крупнее W3; W4a уже пригоден для жизни |
| Вход в e2e | Playwright **подписывает cookie сессии** тестовым `SESSION_SECRET` локального воркера (тот же формат, что [token.ts](../../../platform/apps/worker/src/auth/token.ts)); свежий `sub` на тест | Сервер не получает тестового маршрута; вход через Google проверяется вручную на dev |
| Удалённый аккаунт на другом устройстве | **Эпоха** (вариант A): случайный `meta.epoch`, отдаётся в `GET /api/state`; смена эпохи → снимок принимается целиком, очередь сбрасывается | Тесты W2 «rev 0 после удаления» не меняются |
| Id новых строк | **Id выдаёт вызывающий** (ADR 011): `ToolContext.newId()`; браузер шлёт id оптимистичного прогона в `x-imprint-ids` | Строки браузера и сервера совпадают: нет перемонтирования, отметка сразу после ввода работает |
| Повтор после обрыва | **Занятый id = повтор**: если любой id из `x-imprint-ids` уже есть в строках, вызов уже исполнялся → `unchanged("replayed")` без исполнения | Создающие tools (задача, группа, шаги, события) получают id от клиента — нет дублей. Остальные принимают абсолютные значения (`done: true`, имя, дата) и на повтор отвечают `same_value`. Единственный неидемпотентный — `delete_group` (повтор → `not_found`), поэтому **отказ на сетевой повтор** store принимает молча и перечитывает состояние. Без таблицы вызовов и миграции (тест `SCHEMA_VERSION = 3` не меняется) |
| Код лендинга | Эталон вида и поведения, код пишется заново (компоненты, store, CSS-модули) | Решение пользователя |
| Анимация | `@formkit/auto-animate` (~2 КБ) для списков (FLIP); остальное — CSS (`linear()` для пружины). `motion` — только если понадобится в W4b | Красиво и не громоздко; UX §6: движение — сообщение о действии |
| Роутер | Свой, на `history.pushState` (пять адресов UX §2) | Библиотека не окупается |
| Стили | CSS-модули + токены на `:root`; без Tailwind | Токены 03-DESIGN прямо как переменные |
| `app/` (Android v1) | Не трогается и не архивируется | Рабочее приложение; платформа его не импортирует; W7 строит к нему мост |

Файлы W2-пробника `account.ts`, `health.ts`, `probe.ts` и их тесты **остаются** (правило «тесты не
трогаем без согласия»); `platform/` переиспользует `fetchMe`, `liveUrl`, `parseLive` из `account.ts`.
Удаление или перенос `probe.ts` и перенос `account.ts` в `platform/` — **только с согласия
пользователя**, отдельным коммитом.

**Правило P1 в коде.** eslint для `screens/` и `components/`: импорт из `@imprint/domain` — только
`import type` и константы палитры/иконок (`GROUP_PALETTE`-подобные); запрещены `Date`, `Date.now`,
`Intl.DateTimeFormat` и date-библиотеки. Время, «сегодня» и форматирование дат делает `store/`
через `time/` домена (подписи дат — чистая функция форматирования ключа `YYYY-MM-DD` по языку,
тоже в `store/`).

## 2. Store

**Состояние:**

```ts
interface Base { snapshot: StateSnapshot; epoch: string; rev: number }      // последний серверный
interface Pending { seq: number; name: string; input: unknown; ids: string[] } // ожидает сервера
```

**Вид** = `memoryContext({ peers: [base как BackupData], clock: Date.now, settings: parseSettings(base.settings), ids })`
+ прогон всех `Pending` по порядку с их же `ids` → затем `list_day`, `list_backlog`, `list_groups` на
том же контексте. Результат запоминается до следующего изменения базы, очереди или смены
логического дня (таймер до следующего `dayStart`, вычисленного доменом). UI ничего не сортирует и не
фильтрует.

**`store.run(name, input)`:**
1. Прогон на текущем виде с `newId`, который записывает выданные id → `Pending.ids`. `ok:false`
   локально → плашка сразу, в очередь не идёт. `ok` без изменений (`unchanged`) → в очередь не идёт.
2. В очередь; вид пересчитывается синхронно (до ответа сервера).
3. Очередь шлёт вызовы **по одному, по порядку**: `POST /api/tools/:name`, заголовки
   `x-imprint-conn` и `x-imprint-ids` (если id были выданы). Сетевой сбой → тот же вызов с теми же
   id позже; сервер узнаёт повтор по занятому id.
4. Ответ `ok` или `unchanged` → вызов уходит из очереди. `ok:false` → уходит, плашка
   «Не сохранилось · Повторить» (повтор = новый `run` с тем же `name`/`input`). Исключение: если
   этот вызов уже отправлялся и оборвался по сети, отказ значит «уже применено» — без плашки.
5. Очередь опустела и был хотя бы один коммит или push → `GET /api/state`.

**Серверное состояние** принимается, если `epoch` другой (тогда очередь сбрасывается) или
`rev > seenRev`. Push `{changed, rev}` с `rev > seenRev` → `GET /api/state` (после опустения очереди,
если она не пуста).

**Первый вход:** если в `settings` нет `timezone`, store вызывает `set_user_settings` с поясом
браузера (W3 спек, раздел «Настройки пользователя»).

**Кэш на чтение:** последний принятый снимок в `localStorage` под ключом `imprint.snapshot.<sub>`;
при запуске показывается сразу, затем заменяется ответом `GET /api/state`. Очередь не кэшируется.

## 3. Ошибки

Тихо, без спиннеров на экранах.

| Что случилось | Что видит человек |
|---|---|
| Отказ сервера (`ok:false`) | Откат только этого вызова, плашка «Не сохранилось · Повторить» (5 с) |
| `unchanged` | Ничего |
| Нет сети / 5xx | Очередь ждёт; повтор с теми же `x-imprint-ids`, бэкофф 1→2→4…30 с; через 5 с — метка «нет связи» внизу сайдбара |
| 401 | Экран входа. Вход — редирект через Google, поэтому неотправленные вызовы теряются (сессия живёт 30 дней — редкость; очередь не кэшируется) |
| Сокет закрылся | Переподключение с бэкоффом; на `onopen` — `GET /api/state` |
| Сокет закрыт кодом 4001 | Аккаунт удалён: `GET /api/state` (новая эпоха), очередь сбрасывается |

## 4. Сервер и домен (аддитивно, существующие тесты не меняются)

1. **`ToolContext.newId(): string`.** Вызовы `uuid()` в `compose.ts`, `edit.ts`, `tools/support.ts`
   (`taskEvent`), `tools/groups.ts`, `tools/steps.ts` переходят на id из контекста (`buildContribution` и `doneEvent` получают id
   параметром или генератор). `memoryContext` — опция `ids?: () => string`, по умолчанию `uuid`.
   Порядок вызовов `newId` детерминирован для одинакового состояния; если состояние сервера другое,
   id могут разойтись — серверный снимок всё равно заменит вид. **ADR 011.**
2. **`x-imprint-ids`.** До 128 UUID через запятую; заголовок с неверным форматом, дублями или длиннее
   лимита игнорируется целиком (свои `uuid()`). `SqlStore.execute(name, input, tools, ids?)`:
   - если любой из `ids` уже есть среди задач, групп или событий объекта → вызов уже исполнялся:
     `{ ok: true, changed: false, reason: "replayed" }`, текущий `rev`, без исполнения и рассылки;
   - иначе контекст раздаёт их по очереди; когда список кончился — свой `uuid()`.
3. **Эпоха.** `meta.epoch` создаётся при первой загрузке объекта, если его нет (и заново после
   `deleteAll`). `StateSnapshot.epoch: string`. `ToolCall` и push не меняются.
4. Новых tools и миграций в W4a нет.

## 5. Вид и компоненты

- **Токены** (`styles/tokens.css`): 03-DESIGN и UX §6 — миры День (светлый/тёмный по
  `prefers-color-scheme`) и Meta, `SideBg #232A4B`, 8 цветов групп × 2 тона (значения — из
  `packages/domain` палитры, генерируются в CSS-переменные при старте, чтобы не дублировать).
  Корень: `data-world="day|meta"`, `data-theme="light|dark"`.
- **Шрифты:** Playfair Display (900 / италик 700) и Onest, `woff2` в `public/fonts`, `font-display: swap`,
  `font-variant-numeric: tabular-nums`.
- **Иконки:** `@phosphor-icons/react`, поштучный импорт; regular в интерфейсе, fill для групп.
- **Поповеры:** `@radix-ui/react-popover` с `avoidCollisions`, `collisionPadding`; клики внутри не
  доходят до строки (грабля лендинга). Мобильный лист снизу — W4b.
- **Компоненты** (≤ 300 строк файл): `Shell`, `Sidebar` (`NavItem`, `FilterItem`, `NewGroupField`,
  метка связи), `DayColumn`, `BacklogColumn` (секции групп), `ScrollList` (гаснущие края 28 px,
  только когда есть куда листать), `TaskRow`, `RowActions`, `Checkbox` (зона нажатия ≥ 44 px, CMP-4),
  `Composer` (пилюля + чипы Завтра · Выходные · +7 дней · календарь · группа), `GroupPicker`,
  `DateButton` (прозрачный `input[type=date]` + `showPicker()`), `Toast`.
- **Движение:** auto-animate на списках; CSS-переходы; всё выключено при `prefers-reduced-motion`.

## 6. Объём W4a и W4b

**W4a** (десктоп ≥ 1024 px; уже 1024 px — та же раскладка без адаптации, мобильная — W4b):
- store, live, кэш, эпоха, `newId` + `x-imprint-ids` (с узнаванием повтора);
- вход (кнопка «Войти через Google» на тихом экране) и выход (пункт внизу сайдбара);
- адреса `/`, `/g/<id>`, `/history`, `/settings` (последние два — заглушки мира Meta), «Назад»,
  перезагрузка; запомненный фильтр;
- сайдбар: экраны со счётчиком Дня, фильтры, «+ Группа» полем на месте;
- колонки День и Бэклог (секции групп при «Все задачи», подпись фильтра);
- ввод с чипами даты и группы (включая «Новая группа»), `N`, `Esc`, подсветка новой строки;
- строка: отметка с анимацией; наведение и фокус — лейбл группы, дата, удалить с «Отменить»;
- ru/en; деплой на dev.

**W4b:** повтор; шаги и «Подсказать шаги»; правый клик (название задачи, правка группы: иконка,
цвет, удаление с отменой); перетаскивание задач (dnd-kit, три правила) и порядка групп; мобильная
раскладка (выдвижной сайдбар, тап-ряд, долгий тап, листы снизу, `/g/all`); все e2e UX §8,
скриншот-тесты тем, тест контраста токенов.

## 7. Тесты

- **store** (Vitest, Node, фейковый `api`): действие видно до ответа; отказ откатывает только свой
  вызов; порядок отправки; сетевой повтор с теми же id; смена эпохи; кэш; 401; первый вход ставит пояс.
- **сервер** (vitest-pool-workers): id из заголовка в строках; кривой заголовок игнорируется;
  повтор с занятым id → `replayed`, без исполнения и рассылки; эпоха есть и меняется после
  удаления аккаунта.
- **домен:** `newId` из контекста во всех создающих tools; `memoryContext({ ids })`.
- **компоненты** (Vitest + Testing Library + happy-dom) — только то, чего не видно в e2e: клики в
  `Popover` не доходят до строки, `DateButton` — `type=date`, `N` не перехватывает чужое поле.
- **e2e** (Playwright, Chromium; `wrangler dev` + Vite локально; конфиг отказывается от
  не-localhost `baseURL` — CRIT-1). W4a: таблица ввода (десктоп + чип группы), отметка и снятие,
  дата → Бэклог, удаление и «Отменить», группа из сайдбара и из чипа, адреса + «Назад» +
  перезагрузка, **две вкладки**, нет прокрутки страницы на 1440×900 / 1280×720 / 1024×768, окно у
  правого и нижнего края в пределах экрана.
- `npm run check` — typecheck, lint, unit, build; `npm run e2e` — отдельно (и отдельной задачей CI).
