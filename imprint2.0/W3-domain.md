# W3 — Домен 2.0 на TS

**Цель:** сервер сам вычисляет День (без телефона и без мутирующего rollover), а tools покрывают всё,
что требует [05-web-ux.md](05-web-ux.md).

**Зависит от:** W2 · **Тег:** `web-w3`

## Вход

- Код домена v1 (`app/src/main/java/com/imprint/app/domain/`) и его тесты — **спецификация**, а не
  черновик: логику переносим, а не придумываем заново.
- SPEC §4 (модель, сборка Дня, порядок, rollover), §5.1 (единая точка отбора), решения №9, №17,
  №20–№24.

### Rollover: из мутации в проекцию

В v1 сброс дня — это **действие**: в час сброса `runRolloverIfNeeded` один раз переписывает строки и
ставит флаг `lastRolloverDayKey`. В 2.0 сброс — это **смена аргумента** `logicalToday`: День
пересчитывается из строк и журнала, ничего не записывая.

| Что делал rollover v1 | Как в v1 | Правило проекции 2.0 |
|---|---|---|
| Убрать выполненные одноразовые | Tombstone строки (`deletedAt`) | Одноразовая задача **завершена**, если её последний `DONE`/`UNDONE` — `DONE` с `dayKey < today`. Завершённая не видна в Дне и Бэклоге, но это не удаление: видна в Истории, `UNDONE` в её день возвращает её |
| Перенести в День задачи с наступившим сроком | `location = DAY`, `enteredDayAt = dueDate`, `MOVED_TO_DAY` | Задача бэклога с `dueDate ≤ начало today` — в Дне, ключ сортировки = `dueDate`. **Исключение:** убранная в бэклог в текущий логический день вернётся только завтра |
| Повторяющиеся появления | Уже вычислялись (`DayAssembly`) | Без изменений: по каденции, с учётом `SKIPPED`/`PULLED_TO_DAY` на `today` |
| Следующий шаг цепочки | Мутация `promoteNextChainStep` при `DONE` шага | Как в плане tools (конвейер в `set_done`) — пересмотреть в ADR, если проекция проще |
| Сегодняшние выполненные | Оставались отмеченными до сброса | Без изменений: `DONE` с `dayKey == today` — отмечена, в конце списка |

## W3b — Дельта под UX

Новые версии tools в `packages/domain`. Замороженные документы не меняются; каждый пункт — закрытие
расхождения между [планом tools](../docs/superpowers/plans/2026-09-28-web-tools.md) и `05-web-ux.md`.

| Что | Было в плане tools | Становится (по UX) |
|---|---|---|
| Цвет группы | ARGB из палитры v1, по умолчанию от `hash(id)` | Поле `colorKey` из палитры 8 ключей (UX §5), следующий цвет по кругу; поле `icon` (16 ключей Phosphor, по умолчанию `tag`) |
| Удаление группы | Отказ `not_empty` при живых задачах | Удаление сразу, задачи остаются без группы; `restore_group` возвращает группу и принадлежность задач |
| Добавление | `add_task(where)` | Правило размещения по контексту (UX §3: фильтр × дата, мобильное исключение) — use-case домена, UI передаёт только контекст |
| Бэклог → День | `move_to_day` ставит `dueDate ??= сегодня` | Перетаскивание снимает дату, группа сохраняется (UX §4) |
| День → Бэклог при выбранной группе | — | Задача получает эту группу (UX §4) |
| Шаги | `split_task` | + `suggest_steps` через Gemini в воркере (ключ в wrangler secret, дневная квота в объекте) |
| Шаги ↔ задача | — | `DONE` последнего открытого шага → `DONE` задачи; `UNDONE` шага или новый шаг у выполненной задачи → `UNDONE` задачи (UX §4). Согласовать с конвейером цепочки в том же ADR |
| Группа при вводе | Группа только из фильтра | Явная группа из чипа ввода задаёт группу, место — по-прежнему фильтр × дата (UX §3) |

действия UX — tools.

## Хвосты W3a (из ревью, 2026-09-29)

Мелкие замечания, отложенные при ревью W3a. Каждое закрывается в указанной фазе.

**W3b** (вместе с `move_task`, `set_due_date`, шагами) — закрыты в W3b (ADR 008–010, план 2026-09-29-w3b-ux-delta):
- `move_to_day` на задаче, которую проекция считает `completed`/`hidden`, пишет `MOVED_TO_DAY` и
  отвечает `changed` без видимого эффекта — решить в `move_task` (отказ или явное «вернуть»).
- `list_groups.taskCount` и `delete_group` (`not_empty`) считают завершённые одноразовые — закрывается
  `openCount` и удалением с отвязкой.
- `marksOf` отдаёт общий изменяемый `NO_MARKS` — заморозить или сделать `Marks` readonly.
- Пробелы тестов проекции: два выполненных сохраняют порядок, две группы с общим якорем, рутина
  `doneToday` в Дне и Бэклоге, завершённая датированная задача; DB-3 при каденции без сегодня;
  цикл пропуск → притянуть → пропуск; сценарий «три дня»: результат шага 16, «посылка уходит вниз»
  (сейчас она и так последняя), `idOf` без `!`.
- Косметика: касты `task.dueDate as number`, вложенный тернарник в `set_due_date`.

**W4** (до того, как браузер считает День):
- `isTimeZone` принимает зависящие от движка значения (`"+03:00"`, имена в нижнем регистре) — хранить
  `resolvedOptions().timeZone`, отклонять смещения.
- `dueKey` сохраняет дату при смене пояса только при сдвиге смещения < 12 ч (ADR 007) — нормализовать
  даты при смене пояса в Настройках.
- Тест, что `set_user_settings` рассылает изменение по сокету (сейчас косвенно через `committed`).

**W5** (агенты могут вызывать tools в цикле):
- `locate()` индексирует весь журнал на каждый вызов; `dayStart(today)` пересчитывается на каждую рутину —
  мемоизировать в `Frame` или фильтровать по `taskId`.

**W6:** смена пояса/сброса сдвигает начало окна раньше, а в памяти — старое окно до следующего
пробуждения: в `snapshot()` может не хватать не-отметок одного граничного дня (важно Истории).

**W7** (импорт v1): даты v1, проставленные в момент сброса при `resetHour ≥ 12`; повторяющиеся строки
`DAY` v1 (в 2.0 показываются только по каденции); бывшие рутины, ставшие одноразовыми после `DONE`,
— та же нормализация, что `UNDONE` при выключении повтора (ADR 007).

Без действий: индекс `events_taskId` мало используется хвостом (безвреден); тест на сбой коммита с
настройками (верно по построению); `HALF_DAY` в двух файлах.
