## Эпик 6 — Сопротивляющаяся задача

- Сигнатура: разбита на шаги + облако снято + движения нет → задача **тихо** выходит из ротации
  впечатывания; в списке — нейтральная необязательная подсказка «отложить / разбить / оставить», без
  счётчиков дней и без упрёка (`01-CONCEPT.md §8`).
- Реализация: чистая функция в `packages/domain` + фильтр в функции отбора; подсказка в вебе и на
  телефоне из одной проекции.
- Сначала измерить: сколько задач попадают под сигнатуру на реальных данных.

## Эпик 4 — Страховочные колёса по группам

- Условие старта (решение №24): burndown показывает, что сильная зона вытесняет слабую **несмотря
  на** эпик 5. До этого — только наблюдение.
- Помощь убывает и возвращается по группам, тихо, без объявлений.

## Закреп задачи (ручной приоритет)

Отложен решением №20. Добавить, **только если** данные покажут, что гашение частотой скрывает нужное.
Поле `priority` уже есть в модели и первым стоит в ранжировании.

## Расширение Chrome — десктопное впечатывание

- Отдельный клиент на `packages/domain`, вход через OAuth платформы.
- Показ набора из `get_imprint` (P6); `SHOWN` записывается через tool, поэтому ротация общая для
  телефона и десктопа.
- Отдельный ADR: разрешения расширения, политика Chrome Web Store, несколько профилей.

## Возможности, которые появились благодаря серверу

- Серверные агрегаты статистики, если проекции на клиенте станут тяжёлыми (только измерение, без
  рейтингов и трендов — анти-фича).
- Общие списки — только отдельным ADR (сейчас корень данных — объект пользователя).

## Чего не будет (напоминание из концепта)

Стрики, очки, бейджи, пуши «вернись», награды за заходы, тренды «растёт/падает», объявления о
снятии помощи. Сервер и MCP это не меняют.

## Готово, когда

Каждый эпик закрывается своим тегом, ADR и записью в HISTORY с измерениями «до/после».
