# Фаза 5 — Веб: UX и визуал

**Что это.** Дизайн веб-клиента 2.0 со стороны пользователя: раскладка, навигация, ввод, действия с
задачей, группы, визуальная система. Техническая часть веба (стек, хранилище, синхронизация) —
в [05-web.md](05-web.md); этот документ ложится поверх неё. Мокапы — в [mockups/web/](mockups/web/).

**Статус:** согласовано 2026-09-28 (брейншторм по разделам). История и Настройки — заглушки,
их детальный дизайн отдельно.

## 1. Рамки

**Зачем веб.** Тот же пользователь, что на телефоне, четыре сценария: быстрый ввод за столом,
разбор бэклога, взгляд на День, История. Веб — полноправный клиент, но не место, где хочется
задерживаться: тихий интерфейс, без дашбордов. Впечатывание в вебе **есть**: его выполняет
расширение браузера с плашкой (§9), на телефоне ту же роль играет оверлей.

**Два режима раскладки** по ширине окна:

| Ширина | Режим |
|---|---|
| ≥ 1024 px | **Десктоп**: сайдбар + колонки День и Бэклог + поле ввода внизу |
| < 1024 px | **Мобильный**: одна колонка, сайдбар выдвигается (☰ или свайп от края) |

Планшет в портрете попадает в мобильный режим; отдельной планшетной раскладки нет.

**Ширина на десктопе:** весь интерфейс — блок по центру шириной `clamp(960px, 62vw, 1200px)`,
по бокам фон текущего мира. Строка задачи в колонке ≈ 40 знаков.

**Высота:** интерфейс всегда целиком в окне. Сайдбар, заголовки колонок и поле ввода закреплены;
прокручиваются только списки. Прокрутки страницы нет ни на одном экране.

**Вне рамок (отложено):** детальный дизайн Истории и Настроек (сейчас заглушки с заголовком),
пустые состояния, горячие клавиши кроме `N`, онбординг и экран входа, сворачивание групп в
бэклоге.

## 2. Раскладка и навигация

**Сайдбар** (одинаковый в обоих режимах), сверху вниз:

1. Логотип Imprint.
2. **Экраны:** День (счётчик открытых задач сегодня), История, Настройки.
3. Разделитель, метка «Бэклог».
4. **Фильтры бэклога:** «Все задачи»; группы (иконка в цвете группы, название, счётчик открытых);
   «+ Группа».

Два независимых выбора: **экран** (янтарная полоса слева у пункта) и **фильтр бэклога**
(подсвечен текстом). Клик по группе, пока открыта История или Настройки, возвращает на День с этим
фильтром. Последний фильтр запоминается в `localStorage` браузера (не синхронизируется).

**Десктоп, экран День:** две равные колонки — **День** слева, **Бэклог** справа, между ними
хайрлайн. Под заголовком Бэклога янтарная подпись с текущим фильтром («Все задачи» или имя группы).
При «Все задачи» бэклог разбит на секции по группам (иконка, цвет, имя); задачи без группы —
последняя секция «Без группы». При выбранной группе — просто список. Поле ввода закреплено внизу на
ширину обеих колонок.

**Десктоп, История и Настройки:** заменяют обе колонки и поле ввода; весь экран, включая поля по
бокам, в мире Meta (navy).

**Мобильный:** сверху ☰, по умолчанию День. Выдвижное меню содержит те же пункты; выбор закрывает
меню. Группа → экран Бэклога этой группы, «Все задачи» → весь бэклог. Системная «Назад» из Бэклога,
Истории или Настроек → День. Поле ввода внизу на Дне и в Бэклоге.

**Адреса** (история браузера и перезагрузка не теряют место):

| Адрес | Экран |
|---|---|
| `/` | День |
| `/g/<groupId>` | День с фильтром группы (мобильный: экран этой группы) |
| `/g/all` | весь бэклог (мобильный) |
| `/history` | История |
| `/settings` | Настройки |

## 3. Ввод задачи

**Поле:** «пилюля» «Что не забыть?» с «+». Над ней чипы, как на телефоне:
**Завтра · Выходные · +7 дней · календарь · группа**. Чипа «Сегодня» нет (намеренно). Чипа цели
«→ День» нет.

- **Календарь** открывает **нативный** выбор даты браузера (`<input type="date">`), без
  заготовленных вариантов; выбранная дата показывается в чипе («3 окт»).
- **Группа** (правка 2026-09-28, по лендингу): чип с иконкой `tag` в пунктирной рамке, без текста.
  Клик — список: «Без группы», группы, поле «Новая группа» (Enter создаёт группу по правилам §5 и
  сразу выбирает её). Выбранная группа показывается в чипе иконкой и именем.

**Куда попадает задача:**

| Фильтр в сайдбаре | Без даты | С датой |
|---|---|---|
| «Все задачи» | День, без группы | Бэклог с датой, без группы |
| Группа | Бэклог этой группы | Бэклог этой группы с датой |

Дата «сегодня», выбранная в календаре, равна отсутствию даты.

**Чип группы задаёт только группу, не место:** место — по таблице выше; группа — из чипа, а если
чип не выбран — из фильтра. Пример: «Все задачи» + чип «Дом» + без даты → День, группа «Дом».

**Мобильный:** фильтр задаёт открытый экран. День = «Все задачи»; экран группы = эта группа;
**экран «Все задачи» бэклога: без даты → бэклог без группы** (единственное отличие от десктопа —
иначе задача исчезла бы с экрана, где её добавили).

**Поведение:**
- Чип даты — один за раз, повторный клик снимает; после добавления выбор даты и группы
  сбрасывается.
- **Enter** добавляет; поле очищается и остаётся в фокусе. Пустой или пробельный ввод игнорируется.
- **`N`** откуда угодно ставит фокус в поле (если фокус не в другом поле ввода). **Esc** снимает фокус.
- Новая строка на секунду получает янтарную рамку, которая гаснет. При «уменьшить движение» — без
  анимации.
- Повтор и шаги при вводе не задаются (в вебе v1 дни недели выбирались при добавлении) — это
  иконки на строке после создания (§4).

## 4. Строка задачи

**В покое:** кружок-отметка слева, название, справа мета:
- иконка группы в её цвете, без текста — только в Дне (там группы смешаны); в Бэклоге не нужна:
  при «Все задачи» есть заголовки секций, при выбранной группе она одна;
- в Бэклоге — дата (приглушённо) или повтор «↻ пн чт» (янтарём); в Дне у рутины — глиф ↻.

**Отметка:** только по кружку, увеличенная область нажатия (CMP-4). Анимация как на телефоне
(заливка теплеет до янтаря, галочка проявляется, «pop» 0.82 + пружина). Выполненное в Дне уходит
вниз зачёркнутым. При «уменьшить движение» — без анимации.

**Десктоп, наведение** (и фокус с клавиатуры, Tab): иконки ложатся поверх конца строки с мягким
затуханием; текст не переносится и не прыгает, под иконками обрезается многоточием. Порядок:

1. **Лейбл группы** (иконка + имя, в цвете группы; у задачи без группы — маленькое пунктирное
   окошко с «+», без текста). Клик — тот же список, что у чипа группы в §3.
2. **Дата** — сразу **нативный календарь** браузера, без окна с заготовками («завтра»,
   «выходные»…): прозрачный `<input type="date">` поверх иконки, плюс `showPicker()`, где он
   разрешён. Очистка в календаре = «Без даты». Будущая дата задаче из Дня переносит её в Бэклог.
3. **Повтор** — чипы Пн–Вс и «Не повторять». Повтор делает задачу повторяющейся задачей бэклога;
   появления в Дне считает `core` (как решение №33 v1).
4. **Шаги** — окно «Разбить на шаги», как `SplitDialog` на телефоне: поля шагов, «Подсказать
   шаги» (Gemini через прокси сервера), «Разбить». Операция — в `core`.
   **Шаги и задача — одно состояние:** отметка последнего открытого шага отмечает задачу
   выполненной; снятая отметка шага или новый шаг у выполненной задачи снимают отметку с неё.
   Правило — в `core` (W3b), UI его не повторяет.
5. **Удалить** — сразу, плашка «Задача удалена · Отменить» на 5 с.

**Перетаскивание** — за любую часть строки, кроме кружка и иконок; пунктир показывает место.
- День → Бэклог при «Все задачи»: группа сохраняется, задача встаёт в секцию своей группы.
- День → Бэклог при выбранной группе: задача получает эту группу.
- Бэклог → День: задача сегодняшняя, дата снимается, группа сохраняется.
- Внутри колонки порядок не меняется (его задаёт `core`; ручной порядок — эпик «Закреп», фаза 7).

**Правый клик** — окно «Название задачи»: правка сохраняется по мере ввода, Enter или Esc
закрывают. Левый клик по тексту ничего не открывает.

**Мобильный:**
- **Тап** раскрывает под текстом ряд: перенос (лоток в Дне, солнце в Бэклоге; **только иконка,
  без текста**, так же на Android), лейбл группы, дата, повтор, шаги, удалить. Открыт один ряд за
  раз; тап вне строки сворачивает.
- **Ряд не шире строки:** элементы не переносятся и не сжимаются; всё, включая «удалить», внутри
  рамки строки на ширине 360 px.
- **Раскрытая строка активна:** она подсвечена рамкой постоянно, а наведение курсора (мобильная
  раскладка в узком окне с мышью) на ней ничего не меняет: текст не сворачивается в одну строку,
  иконки наведения не появляются. Эффекты наведения — только у строк десктопной раскладки.
- **Долгий тап** — лист снизу с названием.
- **Свайпов нет** (конфликт с системным «Назад» по свайпу от края в iOS); все действия — в ряду.

**Всплывающие окна** (выбор группы, повтор, шаги, название, правка группы):
- **Никогда не выходят за край** окна или экрана. Десктоп: окно у якоря, прижимается к краю, а если
  не помещается — открывается с другой стороны якоря (выше или левее). Мобильный: **все** окна —
  лист снизу над затемнением.
- **Действия внутри окна его не закрывают** и не сворачивают раскрытый ряд задачи: выбор дней
  повтора, отметка шага, иконка и цвет группы. Закрывают только Esc, клик или тап мимо окна
  (по затемнению) и явное «готово» (Enter). Тап по затемнению закрывает лист, но не сворачивает ряд.
  Грабля лендинга: окно, перерисованное по клику, отцепляет цель клика, и корень экрана принимает
  его за «тап вне строки»; клики внутри окна не должны всплывать дальше окна.

## 5. Группы

**Модель.** В v1 у группы уже есть цвет: `Group.color` (ARGB `Long`, `0` = без цвета), выбирается
при создании из палитры `GroupColors.kt` (SPEC §8.1). В 2.0:
- **цвет** хранится **ключом** из новой палитры (ниже), а не значением — тема подставляет тон под
  фон;
- добавляется **иконка** — ключ из набора ниже.

Оба поля — операции `FieldSet` над группой в `core` (фаза 1). **Цвет не вычисляется из id** —
это хранимое поле, которое пользователь меняет.

**Палитра групп (8 ключей).** Базовый тон работает на тёмных поверхностях как есть (контраст
3,3–7,5 к `SideBg`, `DarkSurface`, `MetaSurface`). На светлых он слишком бледный (1,8–2,9), поэтому
в светлой теме используется затемнённый тон (контраст ≥ 3,2 к `DaySurface` и `DayBg`, WCAG 1.4.11):

| Ключ | Имя | Тёмные поверхности (база) | Светлая тема |
|---|---|---|---|
| `amber` | Янтарь | `#E0A34A` | `#A17535` |
| `terracotta` | Терракота | `#D9775B` | `#BB664E` |
| `rose` | Роза | `#D17A93` | `#B2687D` |
| `plum` | Слива | `#9C86C9` | `#8875AF` |
| `blue` | Синий | `#6F9BD8` | `#5B7FB1` |
| `teal` | Бирюза | `#5EAFB3` | `#49888C` |
| `sage` | Шалфей | `#7FB59A` | `#5E8672` |
| `graphite` | Графит | `#9AA0AB` | `#7A7E87` |

Эта палитра **заменяет** `GroupColors.kt` v1 (индиго, бирюза, охра, …) во всех клиентах 2.0.

**Перенос цвета из v1** (импорт, фаза 6): ARGB → ближайший ключ по тону.

| v1 (`GroupColors.kt`) | Ключ 2.0 |
|---|---|
| indigo `#6C7AE0` | `blue` |
| teal `#3F9D8F` | `teal` |
| ochre `#D98A3D` | `amber` |
| rose `#C15B7E` | `rose` |
| olive `#7E9A4E` | `sage` |
| violet `#9B6BC4` | `plum` |
| sky `#4E8FC0` | `blue` |
| terracotta `#C0663F` | `terracotta` |
| `0` (без цвета) или вне палитры | без цвета (иконка приглушённым `muted`) |

indigo и sky сходятся в `blue` — пользователь перекрасит при желании.

**Иконки (16 ключей Phosphor):** `tag` (по умолчанию), `house`, `briefcase`, `heartbeat`,
`shopping-cart`, `book-open`, `users`, `moon`, `paw-print`, `car`, `airplane`, `barbell`, `plant`,
`wrench`, `graduation-cap`, `baby`. Группы из v1 получают `tag`.

**Создание:** «+ Группа» в сайдбаре превращается в поле на месте; Enter создаёт группу с иконкой
`tag` и **следующим цветом по кругу** (чтобы соседние группы не сливались). То же поле — «Новая
группа» в выборе группы на строке задачи; созданная так группа сразу назначается задаче.

**Правка — правый клик** по группе в сайдбаре: окно справа от пункта — название (обновляется
сразу), сетка иконок, цвета, «Удалить группу». Esc или клик мимо закрывает. Мобильный: долгий тап,
лист снизу.

**Удаление** без подтверждения: задачи группы не удаляются, а остаются без группы; плашка «Группа
удалена · Отменить» на 5 с возвращает и группу, и принадлежность задач.

**Порядок групп** — перетаскиванием в сайдбаре; общий для всех устройств; задаёт порядок секций
в «Все задачи».

**Где видны иконка и цвет:** сайдбар, заголовки секций бэклога, иконка на строке в покое, лейбл
группы при наведении или тапе; позже — История («По группам»).

## 6. Визуальная система

**Миры:**
- **День** (экран День; на мобильном и Бэклог): Light Day или Dark Day — по системе или по выбору
  в Настройках браузера.
- **Meta** (История, Настройки): всегда navy.
- Мира «Вечер» в 2.0 нет.
- Сайдбар — новый токен **`SideBg` `#232A4B`**, одинаковый во всех мирах. Фон по бокам от блока —
  фон текущего мира.
- Динамическая тема (рассвет, закат; 03-DESIGN §3) — выключена по умолчанию, только в мире День;
  окна времени считает `core`.

**Токены** — из [03-DESIGN.md](../docs/knowledge/03-DESIGN.md) как CSS-переменные на `:root`,
переопределённые для тёмной темы. Новые: `SideBg`, 8 цветов групп × 2 тона.

**Шрифты (решение 2026-09-28):** **Playfair Display** — заголовки экранов и янтарные подписи
(италик); вес закреплён тяжёлым (900 / италик 700). **Onest** — интерфейс, текст, цифры; все цифры
табличные (`tnum`, проверено: у Onest есть). **Тот же выбор для Android 2.0** — Onest заменяет
Inter; обновить 03-DESIGN §4 и файлы `res/font` в фазе 3. В вебе — свой хостинг (`@font-face`,
`font-display: swap`), без Google Fonts в проде. Сравнение пар — [mockups/web/fonts.html](mockups/web/fonts.html).

**Формы:** строка 12 px, окна 14 px, пилюли и чипы — полностью круглые. Иконки — только Phosphor
(regular в интерфейсе, fill для иконок групп). Эмодзи в интерфейсе нет.

**Движение** — только как сообщение о действии: отметка, подсветка новой строки, приподнимание при
перетаскивании, появление окон (120 мс), переход тонов темы (700 мс). При «уменьшить движение» всё
выключено.

**Списки:** прокрутка внутри колонки; края гаснут на 28 px, только когда в ту сторону есть что
листать (как `fadingEdges` в 03-DESIGN).

**Доступность:** текст — контраст не ниже AA; иконки групп — не ниже 3:1 в обеих темах (палитра
выше); область нажатия на мобильном ≥ 44 px, включая кружок; все действия строки доступны с
клавиатуры через фокус.

## 7. Граница с `core` (P1)

Правила §3 и §4 — **use-cases `core`**, а не код UI: куда попадает новая задача, что делает
перетаскивание, создание группы со следующим цветом, удаление группы с отвязкой задач. Например,
`addTask(title, date?, context)`, `moveTask(taskId, target, context)`. UI передаёт только контекст
(экран, фильтр). Android получает те же правила без повторной реализации.

Изменения домена для фазы 1: поля группы `color` (ключ) и `icon` (ключ); палитра и набор иконок —
константы `core:contract`; таблица переноса цвета v1 — в импортёре фазы 6.

## 8. Готово, когда

## 9. Плашка (впечатывание)

Главный механизм Imprint: список дел периодически появляется поверх экрана и отпечатывается в
зрительной памяти, вместо безликих уведомлений. Элемент один, поверхности две:

| Где | Как выглядит | Как скрыть |
|---|---|---|
| **Телефон** | Оверлей сверху экрана, поверх любого приложения | Смахнуть вверх (подсказка «Смахните вверх, чтобы скрыть») |
| **Веб** | Расширение браузера: окно выпадает в правом верхнем углу, как у любого расширения | Крестик. Кнопка «Открыть Imprint» ведёт в приложение |

**Содержимое:** простой список, строка = кружок + текст. Групп, дат, повтора, шагов-счётчиков нет.
Одна строка на пункт, длинное обрезается многоточием. Вид строк тот же, что в мире День, чтобы
в памяти оставалась та же картинка, что в приложении.

**Отбор:** первые **5** невыполненных задач Дня, по порядку списка; остальные ждут следующего
показа. Пустой или полностью выполненный День = показа нет.

**Задача с шагами** показывает не своё название, а **первый невыполненный шаг** по порядку.
Пример: «Купить продукты» → шаги «Составить список» (выполнен), «Сходить в магазин», «Купить всё
по списку» → в плашке только «Сходить в магазин». Если все шаги отмечены, а задача ещё открыта,
показывается её название.

**Отметка в плашке** отмечает то, что показано (задачу или шаг, с теми же правилами шаги ↔ задача,
что в §4). Место не добивается: строка остаётся зачёркнутой; когда отмечено всё показанное, плашка
закрывается сама.

Мокап — [mockups/web/overlay.html](mockups/web/overlay.html).
