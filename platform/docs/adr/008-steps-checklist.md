# 008 — Шаги — чек-лист внутри задачи

**Статус:** принято · **Дата:** 2026-09-29

## Контекст
В v1 «разбить облако» превращало задачу в группу-цепочку: первый шаг в Дне, остальные в бэклоге, `DONE`
шага продвигал следующий (`promoteNextChainStep`). UX 2.0 (§4, лендинг) показывает шаги чек-листом под
задачей: задача остаётся на месте, а её отметка и отметки шагов — одно состояние.

## Решение
- Шаг — строка `Task` с `parentId`, указывающим на существующую строку (живую или удалённую). `parentId`,
  указывающий в никуда, — обычная задача (цепочки v1 нормализует импорт W7).
- Проекция не даёт шагу своего места (`locate` → `hidden`): шаги вкладываются в `DayItem.steps` /
  `BacklogItem.steps` в порядке `position`, `createdAt`. Удалённый родитель скрывает свои шаги.
- Отметка шага — по правилу родителя: у одноразовой шаг помнит отметку, у рутины — только на сегодня.
- `syncParent` после `set_done` на шаге, `add_steps`, `delete_task`/`restore_task` шага: есть ≥ 1 живой шаг,
  все сделаны, родитель нет → `DONE` родителю; не все, родитель отмечен → `UNDONE`. Отметка самого
  родителя шаги не трогает. Результат несёт `parent: {id, done}`.
- Отметка шага при открытых остальных делает сделанную задачу несделанной: `UNDONE` родителю (это
  `syncParent` спеки, не ошибка).
- Родитель оценивается по своему правилу (то же, что у шага): одноразовая — по последней отметке за всё
  время (`DONE` в любой день = сделана), рутина — по отметке сегодня. Поэтому шаги задачи, завершённой в
  прошлый день, не двигают её дату завершения: тик или удаление шага при всех сделанных ничего не пишет,
  а снятие отметки с шага пишет `UNDONE` сегодня.
- `add_steps` заменяет `split_task`; конвейер и группа при разбиении уходят. Вложенность — один уровень.
- Инструменты места на шаге → `is_step`; на задаче, завершённой в прошлый день, → `completed`.

## Последствия
- Разбитая задача не меняет группу и место; История видит `DONE` шагов как отдельные события (W6 решит,
  считать ли их).
- Оверлей и напоминания (W5) выбирают задачи верхнего уровня; свой алгоритм для разбитых — позже.
- Пересмотреть, если понадобится вложенность глубже одного уровня.
