# 010 — Цвет группы — ключ, иконка, удаление с отменой

**Статус:** принято · **Дата:** 2026-09-29

## Контекст
v1 хранит цвет группы как ARGB из своей палитры. UX 2.0 (§5): 8 ключей с тоном под тему, 16 иконок,
удаление группы без подтверждения с «Отменить», порядок групп перетаскиванием. Телефон v1 должен
читать строки 2.0.

## Решение
- Миграция 3: `groups.colorKey`, `groups.icon` (TEXT). В типе поля необязательны: строки и снимки v1 их не
  несут (P7); `groupLook` берёт ключ из `colorKey`, иначе из ARGB по таблице UX §5 (и собственным базовым
  тонам 2.0), иначе `null`; иконка — `tag`.
- `color` только выводится: базовый тёмный тон ключа (`argbOf`), `null` → `0`. Любая запись группы пишет
  оба поля вида.
- `create_group`: следующий цвет по кругу после цвета последней живой группы по `position`; первой — `amber`.
- `delete_group` удаляет сразу и отвязывает живые задачи, ставя им `updatedAt` = `deletedAt` группы.
  `restore_group` без хранимого состояния привязывает задачи с `groupId = null` и `updatedAt == deletedAt`
  группы — отвязанные этим удалением и не тронутые после.
- `reorder_groups` принимает полный порядок живых групп.
- Константы палитры и иконок — в домене; тест контраста ≥ 3:1 к поверхностям обеих тем.

## Последствия
- Задача, отвязанная удалением и изменённая до отмены, остаётся без группы — это правка пользователя.
- Совпадение `updatedAt` чужой правки с моментом удаления в ту же миллисекунду вернёт и её — принято.
- Импорт W7 распознаёт и таблицу v1, и базовые тона 2.0 (`colorKeyFromArgb`).
