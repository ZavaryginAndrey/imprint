# 011 — Id новых строк выдаёт вызывающий

**Статус:** принято · **Дата:** 2026-09-30

## Контекст
Веб показывает действие до ответа сервера (ADR 003): тот же tool исполняется в браузере на
`memoryContext`. Если tool берёт id из `uuid()`, у задачи в браузере и на сервере id разные. Отсюда три
беды: строка перемонтируется, когда приходит серверное состояние; действие по только что добавленной
задаче (отметка до ответа) уходит на сервер с неизвестным id → `not_found`; повтор после обрыва сети
создаёт дубль.

## Решение
- `ToolContext.newId()`: каждый id строки или события tool берёт из контекста. `memoryContext` —
  опция `ids`, по умолчанию `uuid`.
- Браузер записывает id, выданные оптимистичным прогоном, и шлёт их в заголовке `x-imprint-ids`
  (до 128 UUID через запятую; кривой заголовок игнорируется целиком).
- Сервер раздаёт их по порядку, дальше — свои. **Занятый id = повтор:** если хоть один из присланных
  id уже есть среди задач, групп или событий объекта, вызов уже исполнялся — ответ
  `{ ok: true, changed: false, reason: "replayed" }` без исполнения и рассылки.

## Последствия
- Пока состояния браузера и сервера совпадают, совпадают и id. Если нет, id разойдутся, и серверный
  снимок заменит вид — как любое расхождение.
- Создающие tools идемпотентны по id. Остальные принимают абсолютные значения и на повтор отвечают
  `same_value`. Исключение — `delete_group` (повтор → `not_found`); store принимает отказ на сетевой
  повтор молча и перечитывает состояние.
- Таблица вызовов и миграция не нужны. Повтор узнаётся, пока событие вызова лежит в окне состояния
  объекта (35 дней).
