# 009 — Серверные асинхронные tools

**Статус:** принято · **Дата:** 2026-09-29

## Контекст
«Подсказать шаги» вызывает Gemini: это сеть, секрет и квота. `runTool` домена синхронный и изоморфный
(ADR 003) — он же работает в браузере и в MCP; туда нельзя ни ключ, ни `await`.

## Решение
- Реестр `SERVER_TOOLS` в `apps/worker/src/tools/`; `UserStore.callTool` ищет имя сначала в нём, потом
  вызывает `SqlStore.execute`. Маршрут `POST /api/tools/:name` не меняется.
- Серверный tool читает зафиксированное состояние (`SqlStore.view()`), строк не пишет, `rev` не меняет,
  по сокету ничего не рассылает. Контракт — тот же `ToolResult`, исключений нет.
- Чистые части — в домене (`suggest/`): контекст, промпт, разбор ответа, `prepareSuggestion`, квота
  `SUGGEST_DAILY_QUOTA = 20` за логический день.
- Квота — счётчик `meta` `suggest:<dayKey>`; слот **резервируется до** `await fetch` (объект в это время
  обслуживает другие запросы) и возвращается при сбое.
- До обращения к модели `suggest_steps` отказывает без вызова и без траты слота: шаг → `reason: "is_step"`,
  задача, завершённая в прошлый день, → `reason: "completed"` (как инструменты места, ADR 008).
- Ошибки: нет ключа → `unavailable`, сбой или таймаут 15 с → `upstream`, квота → `reason: "quota"`.
- Ключ — wrangler secret `GEMINI_API_KEY`, в запросе — заголовок `x-goog-api-key`.

## Последствия
- MCP (W5) регистрирует `ALL_TOOLS` и `SERVER_TOOLS` вместе.
- Браузер не может предсказать результат серверного tool — показывает ожидание.
- Пересмотреть, если серверных tools станет много или им понадобится писать строки.
